# 版权澄清执行手册

> 目标：**功能一个不丢，版权说得清楚。**
> 关联：[CODE-PROVENANCE.md](CODE-PROVENANCE.md)（比对数据）、[ADR-0005](ADR-0005-LICENSE.md)（授权决策）
>
> 这份手册只讲怎么做，不讲为什么要做。为什么见上面两份。

---

## 一、目标与边界

**要达成的三件事**

1. 服务端代码表达全部为独立创作（当前 30.8% 仍是上游原文）
2. 未重写的部分有清晰的来源标注
3. 对外有一套经得起核的说法，而不是「全部原创」

**明确不做**

- 不改表结构、不改接口路径与参数、不改前端
- 不改 git 历史（改历史属于伪造）
- 不为了降相似度去改简单到没有改写空间的代码

## 二、功能保全：四道防线

重写的风险从来不是「改不完」，而是「改坏了没人发现」。这个项目没有集成测试兜底，所以要用流程兜。

### 防线 1：契约冻结

重写的**只有实现**，以下一律不动：

| 不动的东西 | 原因 |
|---|---|
| 数据库表结构、`db/migration/` | 动了要迁移，风险远大于收益 |
| Controller 的路径、参数、返回结构 | 前端、后台、外部调用都依赖 |
| Service 的 public 方法签名 | 调用方零改动才能保证低风险 |
| Redis key 的格式与前缀 | 改了等于线上缓存全失效 |
| 定时任务的 bean 名与 cron | Quartz 表里存了名字，改名任务失联 |

### 防线 2：数据不动

全程不执行 DDL、不跑数据订正。唯一允许的数据库操作是本地起库跑迁移。

### 防线 3：前端不动

`coolpilot-web` 与 `coolpilot-admin` 已经 100% 自研（Nuxt 3 / Vue 3），**不在本次范围内**。
这也意味着前端可以作为「功能是否还在」的探测器 —— 页面崩了，说明后端改坏了。

### 防线 4：每批回归

每批改完，按下面的清单跑一遍，全过才合并：

```bash
# 1. 编译与打包（约 40s）
cd coolpilot-server && mvn -o -DskipTests package

# 2. 全量单测
mvn -o test

# 3. 本地起服务（迁到新代码）
mvn -o spring-boot:run

# 4. 打关键接口（见下表）
```

**接口回归清单**（按批次勾选，不要求全跑 263 个）：

| 批次 | 必测接口 | 验证点 |
|---|---|---|
| A `util/` | `GET /blogs`、`GET /blog?slug=`、`GET /nav` | 访问日志有 IP、归属地不为空 |
| B `service/impl/` | `GET /categories`、`GET /tags`、`GET /moments`、`POST /comment`、`GET /admin/categories` | 列表有数据、缓存生效、新增后列表刷新 |
| C `controller/` | 对应 controller 的读写接口各一个 | 参数与返回结构不变 |
| D `modules/` | `POST /order`、`POST /admin/order/{no}/confirm`、`GET /entitlements` | 状态流转正确、权益发放正确 |
| E `aspect/` | 任一写接口 + 查 `operation_log` | 日志落库、IP 与参数正确 |

**前端冒烟**：`/`、`/archives`、`/blog/{slug}`、`/open-source` 四个页面 200 且内容不空。

## 三、版权澄清：三层动作

### 第 1 层：重写（治本）

按 [CODE-PROVENANCE.md](CODE-PROVENANCE.md) §九 的五个批次，把 66 个文件改成独立实现。

**验收标准（两条同时满足）**

1. 整体相似度 < 0.30
2. 最长连续相同代码块 ≤ 15 行（注释与 import 除外）

复核命令：

```bash
python docs/scripts/similarity.py --base v0.1.0-baseline
```

### 第 2 层：标注（治标，但必要）

**未重写的上游原文文件**，把 `@author` 改成带来源的写法：

```java
/**
 * @author CoolSkyAI (derived from NBlog by Naccl, MIT)
 */
```

这比「全部改成自己」更强 —— 它经得起任何人拿上游代码来比对。
已重写的文件直接署 `CoolSkyAI`。

### 第 3 层：声明（对外）

`LICENSE` + `THIRD-PARTY-NOTICES.md` 已经就位。**重写完成后**才更新这两处的比例数字，
不要在完成前把 LICENSE 改成「全部自有」。

## 四、分批计划

| 批次 | 范围 | 文件 | 行数 | 预估 | 风险 |
|---|---|---:|---:|---|---|
| B | `service/impl/` 分类、标签、动态、评论、Redis 封装 | 6 | 665 | 2–3 天 | 中（缓存 key 不能变） |
| C | `controller/` 16 个 | 16 | 1,558 | 3–4 天 | 中（前端契约） |
| E | `aspect/` 访问与操作日志 | 2 | 298 | 1 天 | 中（安全语义） |
| D | `modules/` 中 trade/community/product/entitlement 的原文部分 | 41 | ~2,300 | 5–7 天 | **高**（订单、支付、权益） |
| A 剩余 | `util/` 其余（不含 Markdown 扩展） | ~18 | ~1,300 | 2–3 天 | 低 |

**顺序说明**：B → C → E → D → A。
先做「有逻辑但风险可控」的，把方法和工具链跑顺；`modules/` 放最后，因为它一坏就是钱的问题。
Markdown 扩展那 12 个文件建议**不做**，理由见 CODE-PROVENANCE §十二（框架约束，属合并原则）。

**每批的 DoD**

- [ ] `mvn package` 通过
- [ ] 单元测试通过（新增类必须有测试）
- [ ] 接口回归清单全绿
- [ ] 相似度复核达标，数字写回 CODE-PROVENANCE §三
- [ ] 单独提交，提交信息写明「相似度 x.xx → y.yy」
- [ ] 不混入功能改动

## 五、对外表述模板

### 场景 1：客户 / 合作方问「这是你开发的吗」

> 是。服务端与前端均为我开发。项目早期基于一个 MIT 协议的开源博客系统（NBlog）搭建，
> 之后的核心业务——商品、交易、权益、技术服务、AI 问答、开源项目研究——都是新增的。
> 代码中仍保留该开源项目的部分基础代码，其版权声明已按要求保留在仓库的
> THIRD-PARTY-NOTICES.md 中。

**不要说**「全部原创，没有用任何开源代码」——这句话最容易被一份 diff 击穿。

### 场景 2：技术尽调 / 投资方核查

直接给三份文件：

| 文件 | 作用 |
|---|---|
| `LICENSE` | 说明整体授权方式 |
| `THIRD-PARTY-NOTICES.md` | 说明第三方来源与 MIT 合规 |
| `docs/CODE-PROVENANCE.md` | 说明自研与派生的比例、判定方法（可复现） |

**主动提供比被问出来强十倍。** 尽调方最怕的不是「有开源代码」，而是「你不知道自己有开源代码」。

### 场景 3：公开说明 / 关于页

> 本站基于自研的 CoolPilot Platform 构建，早期版本参考了开源项目 NBlog 的架构。

一行就够，不需要展开。

## 七、风险与回滚

| 风险 | 表现 | 处置 |
|---|---|---|
| 缓存 key 变化 | 线上缓存全失效，短时变慢 | 重写时把 key 常量抽出来单独核对，diff 必须为空 |
| 事务边界改变 | 部分成功、数据不一致 | 保留原 `@Transactional` 注解位置，只改方法内部 |
| 异常类型改变 | 前端提示变英文/500 | 保留 `throw new ...Exception(...)` 的类型与文案 |
| 定时任务失联 | 关单、浏览量落库停了 | bean 名与 cron 表达式不动 |
| 改坏了没人发现 | 静默错误 | 每批跑接口回归；关键路径补单测 |

**回滚**：每批一个 commit，出问题直接 revert 该 commit，不涉及数据，成本极低。
