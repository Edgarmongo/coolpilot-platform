# 功能地图：CoolPilot Platform 全站

> 依据代码现状（`v1.1.0`，Flyway V28）逐层盘点，不是规划稿。
> 盘点提交 `8888cbb` → 发布提交 `8e92217`，二者代码等价，仅多文档改动。
> 规模：**62 张表 · 263 个接口（后台 76 个）· 前台 34 个页面 · 后台 32 个页面 · 6 个容器**。

## 〇、系统组成

```
浏览器 ──► gateway (nginx, 80/443)
              ├── /**      → web    (Nuxt 3 SSR, 8081)
              ├── /api/**  → api    (Spring Boot, 8091)
              └── /cms/**  → admin  (Vue 3 + Element Plus)
                                   │
                            mysql:8 / redis:7（内网，不映射端口）
```

三端一网关：**web 负责被搜索引擎收录的公开内容，api 是所有业务规则的唯一实现，admin 只做录入与处理**。
admin 不直连数据库，全部走 api，权限与校验只有一份。

## 二、内容与阅读

### 前台

| 页面 | 功能 |
| --- | --- |
| `/` 首页 | 首屏、最新文章（头条 + 卡片）、专题横条、知识产品、技术服务、关注我；无数据区块自动隐藏 |
| `/archives` 技术文章 | 列表/时间线双视图、按专题筛选、侧栏统计与归档 |
| `/blog/{slug}` 文章详情 | 正文（Markdown 渲染 + 标题锚点）、目录侧栏、相关阅读、所属专题、所属项目、关联付费内容、收藏/点赞、评论、密码文章解锁 |
| `/category/{name}`、`/tag/{name}` | 按分类/标签浏览 |
| `/topic`、`/topic/{slug}` | 专题列表与系列导读（按编辑指定顺序） |
| `/moments` 动态 | 时间线 + 点赞 |
| `/friends` 友链 | 公开列表 + 访客申请 |
| `/about` 关于 | 独立页，内容为 Markdown |
| `/search` 搜索 | 关键词搜索 + AI 语义检索两组结果 |

### 后台

文章增删改（Markdown 编辑器、粘贴上传图片、定时可见性、置顶/推荐/密码）、分类与标签管理、专题管理与文章排序、动态发布、评论审核与回复通知、友链审核、关于页编辑。

### 规则要点

- 文章 `content` 存 **Markdown**，读取时统一转 HTML；渲染层对 HTML 内容也安全（v1.0.4 修复）
- 文章唯一 URL 是 `/blog/{slug}`，栏目页只做聚合，不复制正文
- 密码文章的凭证按文章维度存 Cookie，30 天有效

## 五、知识商品与权益

### 商品类型

`COURSE` 视频课程 / `DOC` 付费文档 / `COLUMN` 知识专栏 / `CODE` 代码资源 / `SERVICE` 技术服务

### 前台

- `/knowledge` 商品列表、`/knowledge/{productNo}` 详情（含目录、试看、价格策略）
- 下单前可查权益：`/resource/access` 返回 `NOT_LOGIN / NO_ENTITLEMENT / OK`
- 已购资源通过**一次性 token** 下载（`/file/token` → `/file/download`），链接不可转发

### 后台

商品主数据、价格策略（固定价/起步价/按需报价）、课程与课时、专栏文章绑定、可下载资源、商品分类、博客关联付费内容。

## 六、交易

```
下单 → 生成支付单 → 转账（微信/支付宝/PayPal）→ 后台确认 → 发权益
                     ↘ 超时未付 → 自动关单（定时任务）
```

| 环节 | 前台 | 后台 |
| --- | --- | --- |
| 订单 | 下单、取消、查订单列表与详情 | 查订单、手动关单、销售统计 |
| 支付 | 选渠道、看收款信息、提交转账单号 | 确认到账 / 关闭支付单 |
| 退款 | 申请退款、查进度 | 同意 / 驳回 / 完成退款 |
| 权益 | 查看已购 | 手动发放、回收、批量过期、变更流水 |

**支付是人工转账 + 后台确认**，没有接在线支付网关。`MANUAL_WECHAT / MANUAL_ALIPAY / MANUAL_PAYPAL` 三个渠道。

## 七、技术服务

```
需求（客户提交）→ 评估 → 报价单 → 客户接受/拒绝 → 立项 → 里程碑 → 交付物 → 验收
```

| 阶段 | 前台 | 后台 |
| --- | --- | --- |
| 需求 | `/demand/new` 提交、`/demand/{no}` 查看、取消 | 列表、详情、评估、改状态 |
| 报价 | 接受 / 拒绝 | 创建、修改、发送 |
| 项目 | `/project/{no}` 看进度 | 立项、改状态、里程碑增改与交付 |
| 交付 | 里程碑验收 / 驳回 | 上传交付物、状态流水 |

每个状态变化都写 `service_event`，客户看到的是可追溯的进度，而不是一句「在处理」。

## 八、AI 问答

### 前台

- `/ask` 对话页：SSE 流式回答，带引用来源与相关度
- `/share/{token}` 分享页：把一次问答变成公开可读的页面，支持浏览计数、点赞、评论
- 顶栏/搜索页的「AI 检索」入口：返回片段 + 来源 + 相关度

### 后台

知识库管理（文档 → 分块 → 索引）、模型配置（LLM / Embedding / Rerank 三套）、重建索引、用量统计（token 与耗时）、质量看板（无答案率、引用命中率）、会话日志。

### 技术链路

```
查询改写 → 混合检索（向量 + BM25）→ 重排（none / llm / http）→ 组装上下文 → 流式生成 → 引用回填
```

向量存储与检索策略见 `ADR-0001` / `ADR-0002` / `ADR-0003`。

| 类别 | 数量 | 说明 |

## 十三、现状盘点

### 能完整跑通的

内容全链路（写 → 审 → 读 → 检索 → 收录）、开源观察全链路、作品集、知识商品与权益、交易（含退款）、技术服务全流程、AI 问答与分享、账号体系、后台所有管理页。

### 有明确边界的

| 项 | 现状 | 影响 |
| --- | --- | --- |
| 支付 | 人工转账 + 后台确认 | 无自动对账，订单量上来会卡在确认环节 |
| 定时任务 | 单进程调度 | 多副本部署会重复执行，需改分布式锁 |
| 英文站 | 结构与文案都在，但内容未持续维护 | 英文页面会混入中文文章 |
| 搜索 | `LIKE` 关键词 + 向量检索两套并存 | 结果口径不完全一致，用户可能看到两组不同结果 |
| 访问统计 | 有 `visit_log`，但没有面向栏目的口径 | 无法回答「哪个栏目/项目最受关注」 |
| 前台无移动端导航折叠 | 导航横向滚动 | 7 项在 375px 下需要滑动 |

### 已知技术债（不影响使用，但会在扩容时咬人）

- `blog` 表 18 列，多模块共用；新增内容类型只能靠外挂表（开源观察就是这么做的）
- 部分表注释在入库时按 latin1 写入，`SHOW CREATE TABLE` 看到的是乱码（不影响数据）
- Redis 里的键名带双引号（key 序列化结果），手工运维时容易漏引号删不掉
- 导航、品牌、关于等配置走 Redis 长缓存，改库不会自动生效，必须走后台或清缓存

## 十四、如果继续做，建议的顺序

| 优先级 | 事项 | 为什么 |
| --- | --- | --- |
| P0 | 访问统计口径（栏目/项目/文章） | 现在所有内容决策都是凭感觉 |
| P0 | 支付自动化（至少对账表 + 回调） | 人工确认是最大的运营瓶颈 |
| P1 | 英文站要么补齐要么下线 | 半开状态对 SEO 与可信度都是负分 |
| P1 | 定时任务加分布式锁 | 一旦上多副本就会重复关单/重复落库 |
| P2 | 开源观察的结论档筛选 + RSS | 栏目差异化的下一步 |
| P2 | 搜索口径统一（关键词与向量合并排序） | 两套结果并存会让人困惑 |
