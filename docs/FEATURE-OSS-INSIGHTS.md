## 一、定位

用实测证据回答「这个开源项目能不能变成生意」，以及**什么条件下不能**。

与另一套「项目」的区别：

| | `/projects` 作品集 | `/open-source` 本栏目 |
| --- | --- | --- |
| 内容 | 我自己的作品 | 第三方开源项目 |
| 目的 | 展示能力 | 判断商业价值 |
| 表 | `portfolio` | `oss_project` |
| 状态 | 单一 `enabled` 开关 | 研究状态 + 发布状态双轴 |

两套完全独立，互不影响。

## 二、内容模型

```
oss_project ──┬── oss_project_article ──→ blog（复用现有文章）
              └── oss_project_tag ──────→ tag（复用现有标签）
```

### 2.1 项目档案（`oss_project`，23 列）

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| 身份 | `slug` / `name` | slug 唯一，前台地址 `/open-source/projects/{slug}` |
| 展示 | `summary` / `cover_url` / `license` / `language` | summary 是列表页一句话，写结论不写形容词 |
| 链接 | `repo_url` / `official_url` / `docs_url` | 空则不显示，不占位 |
| 领域 | `category` | 5 个枚举，非外键 |
| 热度 | `stars` / `stars_at` | **只展示，不参与任何排序** |
| 判断 | `verdict` / `assessment_json` | 五档结论 + 七维评估卡 |
| 状态 | `research_status` / `publish_status` / `featured` / `sort` | 见 2.2 |
| 时间 | `last_verified_at` / `create_time` / `update_time` | 前台展示「资料核验于」 |
| 正文 | `description` | Markdown，读取时转 HTML |

### 2.2 两条状态轴（互相独立）

```
research_status:  todo ──→ researching ──→ done
publish_status:   draft ──→ published ──→ archived
```

- 「研究完了但文章没写完」= `done` + `draft`
- 「先发简版再补研究」= `published` + `researching`
- **公开接口只认 `publish_status='published'`**，与研究进度无关

### 2.3 三个枚举

| 枚举 | 值 |
| --- | --- |
| 项目领域 | `ai-project` / `agent` / `data-search` / `devtool` / `enterprise` |
| 结论档 | `watch` / `deploy` / `extend` / `commercial` / `hold` |
| 文章关系 | `business` 商业分析 / `research` 技术研究 / `practice` 实践 / `compare` 对比 |

评估卡七维固定：技术成熟度、市场需求、商业化空间、部署成本、竞争程度、二次开发价值、Insight 适配。
每维三件东西：档位（高/中/低/未评）+ 一句话条件（≤40 字）+ 证据等级（`F/S/T/M/A/?`）。
**不设总分**——一个数字无法表达「在什么条件下值得做什么」。

## 三、前台页面（6 个新页面 + 1 处增量）

### P1 `/open-source` 栏目首页

| 区块 | 数据来源 | 交互与空态 |
| --- | --- | --- |
| 首屏（标题/定位/搜索） | 静态文案 | 搜索回车 → `/open-source/search?q=` |
| 领域芯片（全部 + 5） | `GET /open-source/categories` | 点领域 → `/open-source/category/{code}`，带项目数 |
| 精选研究 | `GET /open-source/featured` | featured 项目的 business 文章；无文章退回项目本身；按钮「阅读分析 / 查看档案」 |
| 最新项目研究 | `GET /open-source/articles?pageSize=6` | 有文章显示文章卡；**无文章退回项目卡**（带「待研究」角标）；都空显示「本期暂无，正在研究」 |
| 研究方法 | 静态 | 四块：技术架构 / 用户与场景 / 商业模式 / 成本与风险 |

### P2 `/open-source/projects` 全部项目

- 卡片网格，`pageSize=12`，分页写进 URL（`?page=2`）可分享
- 排序切换：默认（featured → sort → 更新时间）/ 研究最多（按站内分析篇数，**star 不参与**）
- 领域芯片跳到领域页；空态「该领域暂无已发布项目」

### P3 `/open-source/projects/{slug}` 项目档案

| 区块 | 说明 |
| --- | --- |
| 面包屑 | 首页 / 开源观察 / 项目名；同时输出 `BreadcrumbList` 结构化数据 |
| 标题区 | 名称、一句话简介、License/语言/领域标签、结论档、仓库/官网/文档外链、核验日期 |
| 商业价值评估卡 | 七维表格 + 证据字母（悬停显示含义）+ 结论行 |
| 项目简介 | `description` 渲染为 HTML，标题自动带锚点 |
| 本项目的分析 | 已发布文章按 `sort` + 发布时间排序，带关系类型标签 |
| 相关项目 | 同标签最多 3 个 |
| 页脚声明 | 「结论基于特定版本与环境，不构成交付承诺」 |

异常处理：`assessmentJson` 解析失败 → 只有评估卡区域显示「评估数据异常」，其余照常；项目不存在或未发布 → 真 404。

### P4 `/open-source/category/{code}` 领域页

领域名 + 项目数 + 芯片切换（当前领域高亮）+ 卡片网格。空态提示该领域暂无项目。

### P5 `/open-source/tag/{name}` 标签页

复用 `tag` 表，列出带该标签的项目。与文章标签通用。

### P6 `/open-source/search` 栏目搜索

结果分两组：项目（卡片）、文章（行式，带关系类型与所属项目）。无结果显示提示。搜索是 `LIKE` 匹配项目名/简介/语言与文章标题，不做分词。

### P7 `/blog/{slug}` 文章页增量

正文下方新增「所属项目」卡：项目名 + 一句话 + 结论档，点击回档案页。
**未关联任何项目时不渲染**，不留空白。数据来自 `GET /open-source/blog/{blogId}/project`，与正文并发加载，不阻塞首屏。

## 四、后台功能（内容管理 → 开源观察）

### 列表页

- 筛选：关键词（名称/slug）、发布状态、研究状态、领域
- 表格列：项目（名称 + slug）、领域、结论档、分析篇数、发布状态、研究状态、更新时间
- 行操作：编辑、发布（草稿/归档时）、归档（已发布时）
- 分页 10 条/页

### 编辑抽屉

| 分组 | 内容 |
| --- | --- |
| 基本信息 | 名称、slug、一句话简介、领域、License、语言、仓库/官网/文档、详细介绍（Markdown） |
| 状态与结论 | 研究状态、发布状态、结论档、精选开关、排序、资料核验日期 |
| 评估卡 | 七行，每行：档位下拉 + 条件输入（40 字）+ 证据下拉；**未填的维度不写进 JSON** |
| 标签 | 多选，来自现有标签库（缺的先在「标签管理」建） |
| 关联文章 | 逐行「选文章 + 选关系类型」，可增删；只能选**已发布**文章 |

保存即全量覆盖标签与关联（提交什么就是什么），没有单独的标签/关联接口。

## 六、六条不可绕过的规则

1. **公开只认 published**：mapper 里没有把状态当参数的公开方法，任何查询参数都绕不过去
2. **归档 ≠ 删除**：档案 404，关联记录与文章都保留，历史链接不断
3. **slug 唯一且格式受限**：小写字母/数字/短横线，2–180 位；冲突时提示被哪个项目占用
4. **只能关联已发布文章**：避免给草稿一个可见入口（标题也算泄露）
5. **评估卡解析失败不拖垮整页**：只在评估卡区域降级
6. **star 不作判定依据**：不排序、不打分，只作关注度参考

## 八、与 PRD 的差异（已实现 vs 未实现）

### 有意偏离

| 项 | PRD 写法 | 实际做法 | 原因 |
| --- | --- | --- | --- |
| 标签/关联接口 | 单独两个 PUT | 保存接口内全量覆盖 | 后台整表提交，多接口会出现「正文存了标签没存」的中间态 |
| 评估卡解析位置 | 后端解析后返回对象 | 后端透传原文，页面 try/catch | 少一次可能改变结构的往返，降级逻辑也更简单 |
| 首页列表 | 文章流 | 有文章用文章流，无文章退回项目卡 | 只有 1 个项目时页面不会空 |

### 未实现（PRD 里列了但本期没做）

| 项 | 编号 | 现状 / 影响 |
| --- | --- | --- |
| 栏目 RSS | v1.1 | 无订阅入口，只能靠搜索与内链 |
| 按结论档筛选 | v1.1 | 只能按领域/标签筛，不能「只看值得商业化的」 |
| 项目对比页 | v1.1 | 无法把两个项目并排看评估卡 |
| star 趋势 / 核验记录表 | v1.2 | 只有单次快照，没有历史曲线 |
| 访问统计埋点 | OS-DEV-308 | 不知道哪个项目/哪篇文章被看得多 |
| 搜索词统计 | OS-DEV-403 | 无法用搜索词反推选题 |
| 侧栏（热门项目 + 转化入口） | UI §8 | 视觉稿最终没有侧栏，按稿实现 |
| 分页（领域/标签页） | OS-DEV-209 只要求 `/projects` | 领域/标签页一次返回 48 条，项目多了会截断 |

## 十、一句话总结

**已具备**：一份可发布的项目档案（含七维评估卡与证据等级）、按领域/标签/搜索的三种浏览路径、文章与项目的双向内链、后台完整的录入与双状态管理、可被收录的 SEO 结构。

**还缺的**（按对运营的影响排序）：访问统计 → 结论档筛选 → 栏目 RSS → 项目对比 → 指标历史。
前两个是「知道什么有用」，后三个是「让人多用一点」。
