## 二、结构性决定

### 1. 头部是双行，不是单行

```
第一行：CP 品牌 · 站内搜索 · 中/EN · 我的 · 登录
第二行：首页 · 技术文章 · 开源商业观察 · 技术专题 · 项目 · 知识产品 · 技术服务
```

这是 `layouts/default.vue` 的既有结构，不是新设计。所有效果图必须按双行做，否则落地时还要再改一次。

### 2. 导航 7 项

新增「开源商业观察」，插入在「技术文章」与「技术专题」之间（`sort=25`）。
其余 6 项名称与顺序保持不变。

### 3. 卡片只有一种

白底 + 1px 青边 + 12px 圆角，hover 上浮 2px。**没有「阴影卡片」这种变体**。
需要强调时靠位置与尺寸，不靠阴影。

### 4. 文章正文自成一套排版

`.prose` 负责文章内排版：h2 带左侧竖线、代码块深青底、表格细线、引用浅青底。
与界面排版（15px）分开，正文用 16px/1.85 更适合长阅读。

| 组件 | 类名 / 文件 | 用途 |
| --- | --- | --- |
| 头部 | `.topbar` + `.nav` | 全站 |
| 卡片 | **`components/AppCard.vue`** | 文章、产品、项目 |
| 筛选 | **`components/AppChip.vue`** | 分类、标签筛选 |
| 标签 | **`components/AppTag.vue`** | 技术标签、领域 |
| 按钮 | `.btn` / `.btn-primary` / `.btn-ghost` / `.btn-sm` | 主次操作 |
| 行式列表 | `.article-row` | 文章列表 |
| 侧栏 | `.with-side` + `.side-block` | 列表页、详情页 |
| 状态角标 | `.badge` / `.badge.soft` / `.badge.todo` | 精选、进行中、待研究 |
| 分页 | `.pager` | 列表页 |
| 正文 | `.prose` | Markdown 渲染结果 |
| 页脚 | `footer` | 全站 |

**已落地的三个组件**（`coolpilot-web/components/`）：

- `AppCard`：`tag` / `hover` / `flushBody` 三个 props，支持 `#cover` 具名插槽
- `AppChip`：`active` / `to`；有 `to` 渲染成 NuxtLink（可收录），无 `to` 渲染成 button
- `AppTag`：`variant`（`default` / `field`）与 `to`；不接受任意颜色，避免同语义不同色

按钮、分页、`prose` 尚未组件化，等迁移页面时再抽——现在抽容易抽错粒度。

## 五、落到 Nuxt 的映射

| 原型 | Nuxt 落地 |
| --- | --- |
| `assets/site.css` | 拆进 `assets/css/` 并在 `nuxt.config` 引入；颜色改 CSS 变量 |
| 头部/页脚 | 改 `layouts/default.vue` 的样式，**不改结构** |
| `.card` 等 | 抽成 `components/` 下的通用组件（Card、Chip、Tag、Badge） |
| `.prose` | 作为全局样式，配合后端 `markdownToHtmlExtensions` 的输出 |
| 页面 | 新建或改造 `pages/*.vue`，数据走现有接口 |

**实施顺序建议**：先抽 CSS 变量与基础组件 → 再改首页 → 再改列表/详情 → 最后改产品与服务页。
每步都能独立上线，不会出现「改一半全站乱掉」。

## 六、注意事项

1. **i18n**：所有文案走 `zh-CN.json` / `en.json` 两份 key，不要硬编码中文
2. **SSR**：文章正文、标题、描述必须在服务端输出，不能靠客户端请求拼
3. **示例内容**：原型里的文章卡与商品卡是**版式示例**，不代表已发布内容；上线时以数据库为准
4. **图片**：封面优先用 `cover_url`；无图时用 `AppCover` 生成确定性青线插画（见 §八）。不要用随机网络图，也不要用「首字母色块」——后者在列表里像加载失败
5. **无障碍**：主色 `#00875A` 在白底上对比度约 4.5:1，正文与按钮文字均达到 AA；不要用更浅的绿做正文色

## 七、与线上的对齐（2026-11-20 实测）

用浏览器读取线上站点的计算样式，结果与设计稿初稿有差异。**已经按线上值修正**，过程记录在此，避免以后再猜。

| 项 | 设计稿初稿 | 线上实测 | 处理 |
| --- | --- | --- | --- |
| 主色 | `#0F766E` | **`#00875A`** | 改为线上值 |
| 描边 | `rgba(15,118,110,.12)` | `rgba(0,135,90,.14)` | 改为线上值 |
| 页面底色 | 纯白 | `#F7FAF9` | 改为线上值 |
| 卡片圆角 | 12px | 14px（旧 `.card`） | **保留 12px**（新组件自成一档，迁移后统一） |
| 卡片阴影 | 无 | `0 1px 3px rgba(16,24,40,.04)` | **不加**，靠描边 |
| 导航 | 白色双行 | **深绿 `#006B47` 满色条，白字** | **未改，见下** |

### 为什么主色必须改

新组件要放在现有页面里，紧挨着顶部那条绿导航。`#0F766E`（偏青）和 `#00875A`（偏绿）并排时，肉眼能看出是两种颜色，像没做完。改成一值后，选中态、链接、按钮与导航是同一族。

### 遗留：头部要不要改

这是本次唯一没定的视觉问题。

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A 保留深绿导航**（阶段 1 建议） | 只改内容区，头部一行不动 | 零风险；绿条是这个站最强的识别符号 | 原型里的白色头部只是「另一种可能」，暂不落地 |
| B 换白色双行头部 | 按原型改 `layouts/default.vue` | 更接近设计稿，内容区更突出 | 全站观感一次性变化，需要单独评审 |

**建议先走 A**：内容系统（卡片、列表、正文排版）才是真正需要现代化的部分，头部换色属于品牌决策，可以单独做一次对比再定。

原型页面目前是 B 的形态，实现时按 A 处理即可，两者不冲突——差的只有 `layouts/default.vue` 的一段样式。

## 八、落地记录（2026-11-20，按 B 方案）

§七 里的「头部要不要改」已定：**走 B，白色双行头部**。站长看过整站效果图后要求整站按此风格重构，因此头部不再保留深绿满色条。

### 改了哪些文件

| 文件 | 改动 |
| --- | --- |
| `assets/css/main.css` | 整体重写为站点基础层：复位、排版、容器（1200）、按钮、卡片、标签、行式列表、正文、分页、侧栏 |
| `assets/css/ui-tokens.css` | 保留 `--c-*` 令牌，作为新组件的取值来源 |
| `layouts/default.vue` | 白色吸顶双行头部（胶囊搜索、下划线选中态）+ 双行页脚 |
| `components/AppCover.vue` | 新增：按 seed 生成 6 种青线封面插画，替代灰块占位 |
| `components/PostList.vue` | 列表改为行式（分类标签 + 标题 + 摘要 + 元信息），外套 `.card` |
| `pages/index.vue` | 首屏 + 头条 + 专题横条 + 知识产品 + 技术服务 + 关注我 |
| `pages/archives.vue` | 列表视图（筛选 + 分页 + 侧栏）与时间线视图（`?view=timeline`），视图可切换 |
| `pages/blog/[id].vue` | 面包屑 + 标题区 + 目录侧栏（正文 h2/h3 注入锚点）+ prose 正文 + 相关阅读 |
| `pages/knowledge/index.vue`、`pages/topic/index.vue` | 统一为新卡片与封面 |

### 三条与实现相关的约定

1. **旧类名保留**：`.card` / `.btn` / `.post-item` / `.article` 都还在，只改取值。没逐页重构的页面（关于、服务、订单、问答…）自动继承新视觉，不会半新半旧。
2. **通栏铺色只放在 `.main` 之内**：`100vw` 的横向溢出由 `.main { overflow-x: clip }` 收掉。不能放在 `body` 上——`body` 一旦成为裁剪容器，头部 `position: sticky` 会失效。
3. **正文锚点在渲染时注入**：不改进库数据、不改 CMS 契约，只在把 Markdown 转成的 HTML 交给页面时，用正则给 `h2/h3` 补 `id`，同时生成目录。

### 封面插画的取舍

站内文章大多没有配图。空着会让列表像没做完，随便配图又会让人以为图与内容有关。`AppCover` 按 `id + 标题` 散列出稳定图案，同一篇每次都一样，并明确是装饰（`aria-hidden`）。

## 九、开源观察栏目（v1.1.0 落地）

栏目页沿用同一套基础层，只在**信息密度**上做了区分：栏目是研究型内容，卡片比文章列表更需要"可比较"，因此多了一个结论档徽标。

### 9.1 页面与组件

| 页面 | 结构 |
|---|---|
| `/open-source` | Hero（含栏目搜索）+ 领域芯片（带计数）+ 精选卡 + 最新项目研究 + 研究方法四块 |
| `/open-source/projects` | 卡片网格（`auto-fill minmax(300px,1fr)`）+ 分页 + 排序切换 |
| `/open-source/projects/{slug}` | 面包屑 + 标题区（徽标 / 外链 / 核验日期）+ 七维评估卡 + 正文 + 本项目的分析 + 相关项目 |
| `/open-source/category/{code}`、`/tag/{name}` | 领域 / 标签列表，复用项目卡 |
| `/open-source/search` | 项目与文章两组结果 |

| 组件 | 职责 |
|---|---|
| `OssProjectCard.vue` | 项目卡：封面 / 名称 / 摘要 / 领域与标签 / 结论档 / 篇数 |
| `OssAssessment.vue` | 七维评估卡：档位 + 说明 + 证据等级徽标（F/S/T/M/A/?） |

### 9.2 三个有意为之的取舍

1. **精选卡只有一个入口按钮**。原本两个按钮文案相同（都叫「项目简介」），改成「阅读分析」+「查看档案」，且没有分析文章时不渲染第二个 —— 两个按钮指向同一页是纯粹的视觉噪音。
2. **项目卡按数量自适应列宽**。只有 1 个项目时，固定三栏会空出三分之二；改用 `auto-fill` 后一张卡自动撑满。
3. **评估卡缺数据时不隐藏，而是显示"待验证"**。直接隐藏会让人以为评估维度只有五项；显示灰底的 `?` 才能表达"这一项还没测"。

### 9.3 证据等级的视觉规则

| 等级 | 底色 | 含义 |
|---|---|---|
| F | 灰蓝 | 官方文档 / 仓库事实 |
| S | 浅紫 | 读源码得出 |
| T | 青 | 自己实测 |
| M | 浅橙 | 市场信息 |
| A | 浅黄 | 推断 |
| ? | 浅灰 | 未验证 |

`?` 不能直接拼进类名（`ev-?` 不是合法 CSS 选择器，构建会报 `css-syntax-error`），统一映射成 `ev-unknown`。
