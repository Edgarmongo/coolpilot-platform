## 二、结构性决定

### 1. 头部是双行，不是单行

```
第一行：CP 品牌 · 站内搜索 · 中/EN · 我的 · 登录
第二行：首页 · 技术文章 · 开源商业观察 · 技术专题 · 项目 · 知识产品 · 技术服务
```

这是 `layouts/default.vue` 的既有结构，不是新设计。所有效果图必须按双行做，否则落地时还要再改一次。

### 2. 导航 7 项

新增「开源商业观察」，插入在「技术文章」与「技术专题」之间（`sort=25`）。
其余 6 项名称与顺序保持不变。

### 3. 卡片只有一种

白底 + 1px 青边 + 12px 圆角，hover 上浮 2px。**没有「阴影卡片」这种变体**。
需要强调时靠位置与尺寸，不靠阴影。

### 4. 文章正文自成一套排版

`.prose` 负责文章内排版：h2 带左侧竖线、代码块深青底、表格细线、引用浅青底。
与界面排版（15px）分开，正文用 16px/1.85 更适合长阅读。

## 三、组件清单

| 组件 | 类名 / 文件 | 用途 |
| --- | --- | --- |
| 头部 | `.topbar` + `.nav` | 全站 |
| 卡片 | **`components/AppCard.vue`** | 文章、产品、项目 |
| 筛选 | **`components/AppChip.vue`** | 分类、标签筛选 |
| 标签 | **`components/AppTag.vue`** | 技术标签、领域 |
| 按钮 | `.btn` / `.btn-primary` / `.btn-ghost` / `.btn-sm` | 主次操作 |
| 行式列表 | `.article-row` | 文章列表 |
| 侧栏 | `.with-side` + `.side-block` | 列表页、详情页 |
| 状态角标 | `.badge` / `.badge.soft` / `.badge.todo` | 精选、进行中、待研究 |
| 分页 | `.pager` | 列表页 |
| 正文 | `.prose` | Markdown 渲染结果 |
| 页脚 | `footer` | 全站 |

**已落地的三个组件**（`coolpilot-web/components/`）：

- `AppCard`：`tag` / `hover` / `flushBody` 三个 props，支持 `#cover` 具名插槽
- `AppChip`：`active` / `to`；有 `to` 渲染成 NuxtLink（可收录），无 `to` 渲染成 button
- `AppTag`：`variant`（`default` / `field`）与 `to`；不接受任意颜色，避免同语义不同色

按钮、分页、`prose` 尚未组件化，等迁移页面时再抽——现在抽容易抽错粒度。

## 五、落到 Nuxt 的映射

| 原型 | Nuxt 落地 |
| --- | --- |
| `assets/site.css` | 拆进 `assets/css/` 并在 `nuxt.config` 引入；颜色改 CSS 变量 |
| 头部/页脚 | 改 `layouts/default.vue` 的样式，**不改结构** |
| `.card` 等 | 抽成 `components/` 下的通用组件（Card、Chip、Tag、Badge） |
| `.prose` | 作为全局样式，配合后端 `markdownToHtmlExtensions` 的输出 |
| 页面 | 新建或改造 `pages/*.vue`，数据走现有接口 |

**实施顺序建议**：先抽 CSS 变量与基础组件 → 再改首页 → 再改列表/详情 → 最后改产品与服务页。
每步都能独立上线，不会出现「改一半全站乱掉」。

## 六、注意事项

1. **i18n**：所有文案走 `zh-CN.json` / `en.json` 两份 key，不要硬编码中文
2. **SSR**：文章正文、标题、描述必须在服务端输出，不能靠客户端请求拼
3. **示例内容**：原型里的文章卡与商品卡是**版式示例**，不代表已发布内容；上线时以数据库为准
4. **图片**：封面优先用 `cover_url`，无图时用「首字母 + 浅青底」兜底，不临时画插画
5. **无障碍**：主色 `#00875A` 在白底上对比度约 4.5:1，正文与按钮文字均达到 AA；不要用更浅的绿做正文色

## 七、与线上的对齐（2026-11-20 实测）

用浏览器读取线上站点的计算样式，结果与设计稿初稿有差异。**已经按线上值修正**，过程记录在此，避免以后再猜。

| 项 | 设计稿初稿 | 线上实测 | 处理 |
| --- | --- | --- | --- |
| 主色 | `#0F766E` | **`#00875A`** | 改为线上值 |
| 描边 | `rgba(15,118,110,.12)` | `rgba(0,135,90,.14)` | 改为线上值 |
| 页面底色 | 纯白 | `#F7FAF9` | 改为线上值 |
| 卡片圆角 | 12px | 14px（旧 `.card`） | **保留 12px**（新组件自成一档，迁移后统一） |
| 卡片阴影 | 无 | `0 1px 3px rgba(16,24,40,.04)` | **不加**，靠描边 |
| 导航 | 白色双行 | **深绿 `#006B47` 满色条，白字** | **未改，见下** |

### 为什么主色必须改

新组件要放在现有页面里，紧挨着顶部那条绿导航。`#0F766E`（偏青）和 `#00875A`（偏绿）并排时，肉眼能看出是两种颜色，像没做完。改成一值后，选中态、链接、按钮与导航是同一族。

### 遗留：头部要不要改

这是本次唯一没定的视觉问题。

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **A 保留深绿导航**（阶段 1 建议） | 只改内容区，头部一行不动 | 零风险；绿条是这个站最强的识别符号 | 原型里的白色头部只是「另一种可能」，暂不落地 |
| B 换白色双行头部 | 按原型改 `layouts/default.vue` | 更接近设计稿，内容区更突出 | 全站观感一次性变化，需要单独评审 |

**建议先走 A**：内容系统（卡片、列表、正文排版）才是真正需要现代化的部分，头部换色属于品牌决策，可以单独做一次对比再定。

原型页面目前是 B 的形态，实现时按 A 处理即可，两者不冲突——差的只有 `layouts/default.vue` 的一段样式。
