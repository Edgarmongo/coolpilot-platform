# V1.1b 交易闭环与权益体系

> 落地日期：2026-11-05
> 对应设计：`docs/DATA-MODEL.md` §八 §九、`docs/ED-04-API-DESIGN.md` §三.2–3.5 §四.2–4.3 §五
> 建表脚本：`coolpilot-server/sql/2026-11-05-v1-1b-order-payment-entitlement.sql`

---

## 一、这一版解决了什么

V1.1a 只做到"商品能展示、资源能下载"，但资源被锁在"必须持有权益"后面，而**权益没有任何产生途径**——付费内容实际上不可购买。

V1.1b 打通完整链路：

```
浏览商品 → 下单 → 生成收款信息 → 用户转账 → 提交凭证
        → 后台核对到账 → 确认收款 → 发放权益 → 可阅读/可下载
        → 申请退款 → 审核 → 打款完成 → 撤销权益
```

设计上不依赖微信支付/支付宝商户资质（个人主体通常拿不到），走**人工确认收款**：收款码从数据库读，转账后用户提交付款人姓名 + 时间 + 截图，后台点「确认收款」触发与未来自动回调**完全相同**的发权益逻辑。

## 二、表清单（6 张）

| 表 | 定位 | 关键约束 |
|---|---|---|
| `orders` | 交易契约 | `uk_order_no`；`idx_user_time`、`idx_expire(status, pay_expire_time)` |
| `order_item` | 订单项 + **价格/标题快照** | 商品改价改名不影响历史订单 |
| `payment` | 渠道事实 | `uk_payment_no`、`uk_channel_trade(channel, trade_no)` |
| `refund` | 退款单 | `uk_refund_no`；同订单只允许一条处理中的退款 |
| `entitlement` | 访问授权 | `uk_user_product_type(user_id, product_id, ent_type)` |
| `entitlement_log` | 权益流水 | 只增不改，`GRANT/REVOKE/EXPIRE` |

> `orders` 而非 `order`：`ORDER` 是 MySQL 保留字，全链路要反引号，MyBatis 动态 SQL 容易踩坑。
>
> `payment` 在文档基础上补了 4 个人工收款字段：`payer_name`、`transfer_time`、`proof_file_id`、`confirm_user_id`。没有这些字段就无法核对线下转账。

## 三、状态机

### 订单 `orders.status`

```
PENDING_PAY ──用户提交凭证──> PENDING_CONFIRM ──确认收款──> PAID ──> COMPLETED
     │                              │
     ├── 用户取消 ──> CANCELLED      └── 超时 ──> CLOSED
     └── 超时 ─────> CLOSED

PAID / COMPLETED ──申请退款──> REFUNDING ──打款完成──> REFUNDED
                                   └── 拒绝 ──> COMPLETED（回退）
```

### 支付 `payment.status`

```
INIT ──提交凭证──> WAIT_CONFIRM ──确认收款──> SUCCESS
  └──────────确认收款──────────┘
  └── FAIL / CLOSED
```

### 退款 `refund.status`

```
APPLIED ──同意──> APPROVED ──确认已打款──> SUCCESS
    └── 拒绝 ──> REJECTED
```

> 退款刻意做成三段而不是一步到位：人工渠道要真的去微信/支付宝/PayPal 操作，中途失败可以停在 `APPROVED` 重试，不会出现"钱没退但权益已撤"。

### 权益 `entitlement.status`

`ACTIVE` / `EXPIRED` / `REVOKED`；`ent_type` = `ACCESS`（阅读）/ `DOWNLOAD`（下载）/ `LEARN`（学习）。

## 四、一致性设计（这一版最要紧的部分）

### 1. 发权益只有一个出口

`PaymentService.onPaid(paymentNo, tradeNo, operatorId, remark, raw)` 是唯一入口：

```
条件更新 payment: INIT|WAIT_CONFIRM → SUCCESS   ← 影响行数必须为 1
  ↓
条件更新 orders:  PENDING_PAY|PENDING_CONFIRM → PAID
  ↓
entitlementService.grantForOrder()  → ACCESS（+ 有资源时 DOWNLOAD）
  ↓
product.sales_count += quantity
  ↓
orders → COMPLETED
```

- 重复点击「确认收款」、未来渠道重复回调，都会因为 `markSuccess` 返回 0 而直接返回 `{confirmed:false}`，**不会重复发权益、不会重复加销量**。
- 订单处于 `CANCELLED/CLOSED/REFUNDING` 时确认收款会抛错并回滚支付单状态，避免"钱收了但订单已关"。

### 2. 撤销必须按订单精确定位

```sql
UPDATE entitlement SET status='REVOKED' WHERE order_no = ? AND status='ACTIVE'
```

不能按 `user_id + product_id` 删：用户可能先买过一次（已退款）又买一次，只删一条会误删后来的合法权益。

### 3. 金额只由服务端算

下单请求只收 `productNo`，价格取商品当前 `price`；`quantity` 数字商品固定为 1，从根源上杜绝前端改价。

### 4. 重复下单防护

1. 已有未过期的 `PENDING_PAY` 订单 → 直接复用，不新建；
2. Redis `SETNX order:submit:{userId}:{productId}` 10 秒锁，挡住连点；
3. Redis 不可用时自动退化为仅依赖第 1 条（不影响可用性）。

### 5. 下载权限接入权益

`FileService.resolveForDownload()` 之前对商品资源一律拒绝，现在改为：

```
文件公开 / 我是上传者 / 站点所有者 → 放行
文件属于某商品资源 → 持有该商品任一 ACTIVE 权益才放行
其它 → 拒绝
```

下载凭证 payload 扩展为 `fileId:userId:expireAt:privileged`，`privileged=1` 用于后台查看用户上传的付款凭证（下载请求本身不带登录头，无法在下载阶段判断角色）。

## 五、接口清单

### 5.1 前台（均需登录，只能操作自己的数据）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/order` | 下单 `{productNo}`，返回订单详情 |
| GET | `/order/{orderNo}` | 订单详情（含订单项、支付单、退款单、权益） |
| GET | `/orders` | 我的订单，`status` `pageNum` `pageSize` |
| POST | `/order/{orderNo}/cancel` | 取消，仅 `PENDING_PAY` |
| GET | `/payment/channels` | 可选收款渠道 |
| POST | `/payment` | 生成收款信息 `{orderNo, channel}` |
| GET | `/payment/{paymentNo}` | 轮询支付/订单状态 |
| POST | `/payment/{paymentNo}/manual-confirm` | 提交凭证 `{payerName, transferTime, proofFileId}` |
| POST | `/refund` | 申请退款 `{orderNo, reason}` |
| GET | `/refund/{refundNo}` / `/refunds` | 退款进度 |
| GET | `/entitlements` | 我的权益 |
| GET | `/resource/access?productNo=` | 是否可访问，返回 `{accessible, reason}` |

`reason` 取值：`FREE` / `PURCHASED` / `OWNER` / `NOT_PURCHASED` / `EXPIRED` / `REVOKED` / `NOT_LOGIN` / `NOT_FOUND`。
前端据此显示「购买 / 续期 / 联系客服」，而不是弹一个 403。

## 六、收款配置怎么改

收款码不写死在代码里，存在 `site_setting`（`type = 5`）：

| `name_en` | 含义 | 默认值 |
|---|---|---|
| `wechatQr` | 微信收款码图片地址 | `/img/wechat-qr.png` |
| `alipayQr` | 支付宝收款码图片地址 | `/img/alipay-qr.png` |
| `paypalUrl` | PayPal 收款链接 | `https://paypal.me/yourname` |
| `payeeName` | 收款人姓名 | 空 |

替换方式：

```sql
UPDATE site_setting SET value = '/img/my-wechat.png' WHERE name_en = 'wechatQr';
```

图片放 `coolpilot-web/public/img/` 下即可直接被前台访问。

## 七、已验证链路（本地实测）

| 步骤 | 结果 |
|---|---|
| 访客注册登录 `buyer01` | 拿到 token，`user.id = 2` |
| `GET /resource/access` | `accessible=false, reason=NOT_PURCHASED` |
| `POST /order` | 生成 `O202611050058375672`，`PENDING_PAY`，金额 199.00 |
| `POST /payment` | 生成 `PAY…0988`，返回收款码与"订单尾号 375672"备注提示 |
| `POST /payment/{no}/manual-confirm` | 支付单 `WAIT_CONFIRM`，订单 `PENDING_CONFIRM` |
| 后台 `GET /admin/payments?status=WAIT_CONFIRM` | 能看到付款人「张三」与转账时间 |
| 后台 `confirm` | 订单 `COMPLETED`，`paidTime` 写入，权益 `ACCESS/ACTIVE`，`sales_count=1` |
| 再点一次 `confirm` | `{"confirmed":false,"message":"该支付单此前已确认，未重复发放"}` |
| `POST /refund` | `APPLIED`，订单 `REFUNDING` |
| `approve` → `finish` | 退款 `SUCCESS`，订单 `REFUNDED`，权益 `REVOKED` |
| `GET /resource/access` | `accessible=false, reason=REVOKED` |
| `GET /admin/stats/sales` | 销售额 199、退款 199、净额 0 |
