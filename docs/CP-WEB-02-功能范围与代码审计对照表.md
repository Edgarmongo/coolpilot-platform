## 4 项目展示系统设计（CP-WEB-08）

### 4.1 硬冲突：`project` 这个表名已经被占用

```sql
-- 现有表，技术服务项目进度（客户视角）
project(id, project_no, demand_id, quote_id, order_no, user_id,
        name, amount, status, start_date, end_date, create_time, update_time)
```

**新表不能叫 `project`**，也不能叫 `project_detail`（容易和它混）。

建议表名：**`portfolio`**（作品集）。备选：`showcase_project`。

前台路由仍用 `/projects`（URL 层不冲突，用户可见的语义是对的）。

### 4.2 表结构：1 张表就够，不需要 `project_detail`

```sql
portfolio (
  id            bigint PK
  slug          varchar(64)  UNIQUE      -- /projects/[slug]
  name          varchar(100)             -- 项目名
  summary       varchar(255)             -- 列表页一句话简介
  cover_file_id bigint                   -- 封面，关联 file.id
  tech_stack    varchar(255)             -- "Java, Spring Boot, Vue, MySQL"
  repo_url      varchar(512)             -- GitHub 地址
  demo_url      varchar(512)             -- 可选演示地址
  status        varchar(16)              -- ACTIVE/MAINTAINING/WIP/ARCHIVED
  content       longtext                 -- Markdown 详情
  sort          int
  enabled       bit(1)
  create_time / update_time
)
```

### 4.3 为什么不需要第二张表（有确凿依据）

你提到「`project_detail` 可以先采用现有富文本内容能力，不一定需要第二张表」——**核查后确认成立**：

- 后台商品详情就是 `el-input type="textarea"` + **Markdown**（`ProductList.vue:148`，占位文案明确写「支持 Markdown，前台渲染为 HTML；截图后可直接 Ctrl+V 粘贴」）
- 后端统一入口 `MarkdownUtils.markdownToHtmlExtensions(md)`，已被文章、商品、关于、动态、友链五处复用
- 前台统一 `v-html` 渲染（`pages/blog/[id].vue:12`、`pages/knowledge/[no].vue:30`）

因此详情页要求的「项目背景 / 系统架构 / 核心功能 / 技术选型 / 核心技术实现 / 项目截图」，**全部写在 `content` 里用 `##` 分段**即可，页面按顺序渲染，后台只有一个大文本框。

**截图**：直接复用现有粘贴贴图（`useImagePaste` composable + `/admin/file/upload`），`bizType` 传 `PORTFOLIO` 即可，无需改后端。

**「相关技术文章」**：首期在 `content` 里手写链接（零成本）；等确实需要自动关联时，再加 `portfolio_article` 关联表（参照 `topic_article`）。**不要为上列表就加表。**

## 7 技术缺口（影响内容运营与引流）

| 缺口 | 影响 | 归属 |
|---|---|---|
| 文章页 `description` 全站同一句 | 搜索结果摘要全都一样 | CP-WEB-07 |
| 无 `canonical` | 同一内容多 URL 时分散权重 | CP-WEB-07 |
| 无 OG 卡片 | 分享到微信/社群**没有缩略图**，直接影响点击率 | CP-WEB-07 |
| 无 JSON-LD | 拿不到富摘要 | P1 |
| 标签体系为空（0 条） | 文章只能按分类找 | P1 |
| `visit_log` 无来源字段 | 不知道流量从哪个平台来 | P2 |

**优先级判断**：OG 卡片对「自媒体引流」的边际收益最高——你现在就要往微信社群、小红书分发链接，没有缩略图的链接点击率明显更低。
