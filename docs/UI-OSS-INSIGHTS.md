## 二、这版稿子暴露的关键问题：卡片是文章，不是项目

「最新项目分析」的四张卡，标题都是文章标题，带「阅读 8 分钟」。

也就是说：**首页列表是文章流，不是项目列表。**

这跟我的初版设计不一样——原设计 `/open-source/projects` 返回项目，卡片显示项目名 + 篇数。
按视觉稿，需要改成：

```
卡片 = 一篇文章 + 它所属的项目
```

影响三处：

| 项 | v1 设计 | 改为 |
| --- | --- | --- |
| 首页「最新项目分析」 | 取项目列表 | 取**文章流**（按发布时间） |
| 卡片信息 | 项目名 / 结论 / 篇数 | 文章标题 / 类型 / 摘要 / 日期 / 阅读时长 + 所属项目 |
| 精选推荐 | 取 `featured` 项目 | 取 `featured` 项目的代表文章，链接到文章 |

**为什么接受这个改法**：文章流有更多入口（一个项目 4 篇 = 4 个可点击标题 + 4 个独立 URL 可被收录），
而项目列表在只有 1 个项目时页面会很空。

### 需要新增的接口

```
GET /open-source/articles?pageNum=&category=&tag=&q=
```

返回 `blog` join `oss_project_article` join `oss_project`，只含
`项目 published` + `文章 is_published`，字段：

```json
{
  "id": 12, "title": "...", "slug": "crawl4ai-business",
  "description": "一句摘要", "coverUrl": "...", "readTime": 8, "createTime": "2026-11-10",
  "relationType": "business",
  "project": { "slug": "crawl4ai", "name": "Crawl4AI", "verdict": "deploy" }
}
```

`/open-source/projects` 仍保留，给「查看更多 →」的列表页与侧栏用。

## 三、精选推荐的取数口径

稿里大卡是「Crawl4AI: 开源网页采集框架的商业价值分析」，带 `Featured` 角标。

**定为**：

```
oss_project.featured = 1
  → 取该项目 relation_type='business' 的最新一篇已发布文章
  → 渲染大卡，点击进文章
  → 卡上另给「项目档案 →」次链接
```

**没有 business 文章时**：退回渲染项目简介，点击进档案页。
不用 `blog.is_recommend`——那个字段已被站内「随机推荐文章」占用（`BlogMapper.xml:172`），
混用会让栏目文章出现在全站随机推荐里，语义不清。

## 四、侧栏「热门项目」的排序

稿中每项带星数（12.8k / 8.6k / 6.2k …）。

**问题**：按 star 排序等于把 star 当价值信号，与评估卡「star 不作判定依据」自相矛盾。

**建议**：

- 排序用 **站内分析篇数 → 最近更新时间**
- star 仍展示，但**降级为辅助信息**，并在项目档案页明确写「仅关注度参考」
- 侧栏标题可保留「热门项目」，但排序逻辑不是热度而是「研究密度」

这样栏目传达的信号是「我们研究得多的项目」，而不是「star 多的项目」——后者任何导航站都能做。

## 五、专题集合：建议真的建一个

稿里「专题集合」有三张卡（AI Agent 专题 / 数据采集专题 / 企业级开源），都带篇数。

现状：`topic` 表为空。空表渲染出来就是三张空卡，所以第一版我建议不渲染。

**但更好的做法是把 Crawl4AI 的 12 篇系列建成一个真实专题**：

```
topic: Crawl4AI 深度研究
  ├─ 商业价值分析
  ├─ 核心架构与运行机制
  ├─ AsyncWebCrawler 深度解析
  └─ ...（按发布进度陆续挂入）
```

这样专题区第一天上线就有真实内容，且 `topic_article` 的排序能力正好用来做「系列导读」。

**结论**：专题区保留，MVP 至少 1 个真实专题。若最终不做专题，则该区块整体不渲染（不显示空卡）。

## 九、卡片信息层级（以稿为准，两处微调）

```
[封面图]            ← cover_url，无则首字母 + 浅青底
类型标签             ← relationType：商业分析 / 技术研究 / 实践 / 对比
标题（2 行截断）
摘要（2 行截断）
领域 + 标签（≤3）
日期 · 阅读 N 分钟    ← 改为「更新于 YYYY.MM.DD」避免与发布时间混淆
```

两处微调：

1. 日期文案统一「更新于」，不用裸日期
2. 领域标签与普通标签视觉上区分（领域用实心浅青底，技术标签用描边）
