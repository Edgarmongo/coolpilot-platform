# UI 方向：开源项目商业观察

> 输入：2026-11-20 桌面端静态视觉提案（非最终稿）
> 结论：**方向接受，8 处需调整**。调整后再出档案页与文章页增量设计。
> 配套 `PRD-OSS-INSIGHTS.md` v1.2、`DATA-MODEL-OSS.md` v2。

---

## 一、方向判断

这张稿子做对了一件事：**它看起来像一个研究媒体，不像一个 GitHub 项目列表。**

具体做对的四点：

| 点 | 为什么对 |
| --- | --- |
| 首屏给「定位 + 价值主张」而不是罗列项目 | 读者先知道这个栏目凭什么值得看 |
| 「重点研究」单独成块 | 一个栏目不需要平铺，需要主次 |
| 项目卡片带「结论/类型 + 日期」 | 暗示这是持续更新的研究，不是静态目录 |
| 底部「研究方法」四块 | 把方法论摆出来，是最好的差异化说明 |

**保留这四点。**

## 二、与现网视觉语言的差异

| 项 | 现网 | 效果图 | 处理 |
| --- | --- | --- | --- |
| 主色 | **青 `#0F766E`**（`rgba(15,118,110,…)` 用于边框/底色，全站 15 处） | 蓝 `#2563EB` 系 | **改用青** |
| 卡片 | 白底 + `1px solid rgba(15,118,110,.12)` + 12px 圆角 + hover 上浮 2px | 无边框 + 阴影 | **沿用现网** |
| 标题字重 | 常规字重 + 字距 | 较重的黑体 | 可用，但不要超过首页主标题 |
| 页面底色 | `#f5f8f7` 系浅青灰 | 纯白 | 沿用现网 |

> 蓝色不是不能用，但它会让这个栏目看起来像「另一个站」。既然定位是站内栏目，
> 视觉上必须能一眼认出是 CoolSkyAI。

## 三、8 处需要调整

### 1. 导航：这张稿是重新设计的导航，不是现有导航

| 效果图 | 现网（`nav_menu` 中 `visible=1`） |
| --- | --- |
| 首页 | 首页 |
| 文章 | **技术文章** `/archives` |
| 开源商业观察 | — |
| 技术课程 | **知识产品** `/knowledge` |
| 关于 | 关于（`visible=0`，当前隐藏） |
| — | **技术专题** `/topic`（被删） |
| — | **项目** `/projects`（被删） |
| — | **技术服务** `/service`（被删） |

**问题**：如果照稿实现，技术专题、项目、技术服务三个已有入口会从导航消失。

**建议**：保留现有 6 项，把「开源商业观察」作为第 7 项插入（sort 45，位于「项目」之后）。
不在此次改名（技术文章→文章、知识产品→技术课程属于全站 IA 调整，另开任务）。

> 这条与 PRD §4.1 是同一件事，视觉稿实际上已经把答案指向「方案 A」。

### 2. 「最新项目研究」里的三个项目我们没有研究过

稿中 Hermes Agent / Swirl Search / Milvus 各带日期（2026.11.10 / 11.08 / 11.05），
视觉上等于宣告「这三篇已经发布」。

**事实**：这三项目前零实测，按 `ARTICLE-STANDARD.md` 不能发。

**建议**：上线的第一期只放已发布的真实项目。卡片不足 3 个时保持两列/单列，不要用占位项目凑数。
日期统一改为「**更新于** YYYY.MM.DD」，避免被理解成「某天发了一篇」。

### 3. 卡片元信息含义不清

稿中写「商业价值分析 · 2026.11.10」——是文章类型还是项目状态？

**建议**：改为 `N 篇分析 · 更新于 YYYY.MM.DD`。
类型留给卡片上的标签区（Agent / 自动化），不要把「最新一篇的类型」当成整个项目的信息。

### 4. 缺少搜索

PRD 要求栏目内搜索（项目名 + 技术关键词），稿里只有右侧一个全站搜索图标。

**建议**：Hero 区下方加一个搜索框（与 PRD §4 P5 对应），
placeholder：`搜索项目或技术，如 crawl4ai / 数据采集`。

### 5. 封面图没有素材

卡片顶部是插画，但我们现在只有 Crawl4AI 一张 SVG 封面，其余没有。

**建议**：沿用 `/projects` 现成的兜底方案——`cover_url` 有则显示，无则显示「首字母 + 浅青底」
（`projects/index.vue` 的 `.cover-empty` 逻辑可直接复用）。不为每个项目临时画插画。

### 6. 「重点研究」的链接目标

稿中按钮写「阅读分析 →」，指向不明：是文章还是项目？

**建议**：指向**项目档案页**。理由是档案是聚合入口，读者从档案再进具体文章；
如果直接跳单篇文章，读者会以为这个项目只有一篇。

### 7. 分类 chip 数量

稿中 5 个（AI 开源项目 / Agent 与自动化 / 数据采集与搜索 / 开发者工具 / 企业级开源软件）。

**这一条反而暴露了数据模型的问题**：我初稿把「开源商业模式」也列为项目领域，共 6 个。
但「商业模式」是分析视角，不是技术领域。已按稿改为 5 个（`DATA-MODEL-OSS.md` §2.4）。

**建议**：保持 5 个 + 「全部」，共 6 个 chip，一行放得下。

### 8. 缺「查看更多」的落点

稿右上角有「查看更多 →」，但 PRD 的页面清单里没有「全部项目列表页」。

**建议**：新增 `/open-source/projects` 列表页（分页，支持领域与标签筛选）。
否则这个按钮无处可去。

## 四、首页区块规格（确认版）

| # | 区块 | 数据来源 | 交互 |
| --- | --- | --- | --- |
| 1 | Hero | 静态文案 | 搜索框 → `/open-source/search?q=` |
| 2 | 领域 chips | `GET /open-source/categories`（含计数） | 点击 → `/open-source/category/{code}` |
| 3 | 重点研究 | `featured=1` 且 `published`，取 1 条 | → `/open-source/projects/{slug}` |
| 4 | 最新项目研究 | `published`，按 `update_time` 倒序，取 3–6 条 | → 项目档案；「查看更多」→ `/open-source/projects` |
| 5 | 研究方法 | 静态四块（技术架构 / 用户与场景 / 商业模式 / 成本与风险） | 无 |
| 6 | 专题（可选） | `GET /topics` | MVP 阶段专题为空，**先不渲染该区块** |

**空状态**：区块标题保留，内容区显示「本期暂无，正在研究」。
区块整体隐藏会让页面看起来像没做完。

## 五、待设计的两个页面

### 5.1 项目档案页 `/open-source/projects/[slug]`

必须包含（顺序按 PRD §4 P2）：

1. 返回 + 项目名 + 一句话定位
2. 元信息行：License / 语言 / 领域 / 结论档
3. 外链行：GitHub / 官网 / 文档
4. 核验行：资料核验于 YYYY-MM-DD · Star N（仅关注度参考）
5. **评估卡七项**（level + note + 证据标记）← 这是与普通项目页最大的差别
6. 结论一句话 + 触发条件
7. 正文（Markdown 渲染）
8. 关联文章列表（带 `relationType` 标签）
9. 相关项目（同标签 ≤ 3）
10. 页脚固定声明：「结论基于特定版本与环境，不构成交付承诺」

### 5.2 文章页增量 `/blog/[id]`

只在正文底部加一块「所属项目」卡：项目名 + 结论档 + 箭头。
其余沿用现有文章页，不改版式。
