## 关于文件数量

原任务卡要求每个审计拆成 7 个子文件（`01-project-overview.md` … `07-known-issues.md`），共 21 个。实际交付合并为 3 个文件、每文件内含对应小节，原因：

1. 三份审计的关键结论高度交叉（例如"JWT 密钥默认值"同时属于基线问题和安全问题），拆开后需要反复互相引用
2. 21 个平均 30 行的碎片文件，检索成本高于收益
3. 每份报告内部仍严格保留 01–07 的小节编号，可按编号定位

如需拆分，脚本可按 `## 0X` 分割，内容无需重写。
